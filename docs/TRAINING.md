# Подготовка обучения

Обучаются веса отдельной ASR-модели. Чат и VEGAS от чтения проектов не меняют
свои веса. В этом репозитории обучение пока не запускалось.

## Порядок эксперимента

1. Экспортировать текст, цвета говорящих, таймкоды и ссылки на исходные записи.
2. Отсеять заведомо неподходящие пары. Восстановить произнесённые слова вместо
   звёздочек, цифровых замен букв и переводных подписей.
3. Выровнять границы примеров по речи. Подпись в монтажном проекте может
   появляться позже начала фразы или включать текст, не произносимый целиком.
4. Проверить небольшой набор вручную и поставить `alignment_reviewed=true` и
   `training_approved=true`. Эти поля нельзя автоматически заменить по одному WER.
5. Разделить записи на обучение, validation и test. Перемонтированные версии
   одной записи относятся к одной группе. Test не участвует в подборе параметров.
6. Сравнить готовые модели на одном фиксированном наборе. Отдельно проверить
   целые ролики, поскольку короткие подписи не отражают все ошибки длинного аудио.
7. Дообучить выбранный GigaAM на train. Начать с небольшого batch, activation
   checkpointing и измерения VRAM. Остановку выбирать по validation. LoRA остаётся
   отдельным вариантом для Whisper/Qwen, если они будут выбраны по новой оценке.
8. Проверить лучшую конфигурацию на отложенном test и новых роликах.

Команда `benchmark` по умолчанию использует validation для выбора базовой модели.
Первый пробный замер Whisper был выполнен на 30 строках test до этого уточнения.
Он считается исследовательским. Для итоговой оценки после выбора и обучения
нужен новый, ранее не просмотренный набор записей. Результат на использованных
для выбора примерах не является независимой итоговой оценкой.

Профиль `research` уже содержит PyTorch CUDA для сравнения и выравнивания.
Обучающий entrypoint и зависимости тренера следует добавить после проверки
датасета. Они не нужны рабочему контейнеру распознавания с CTranslate2.
Конвертированная CTranslate2-модель служит для inference. Для LoRA нужны исходные
веса совместимой модели Transformers и отдельный экспорт после обучения.

## Текущая подготовка

`stage-dataset` создаёт приватные WAV 16 kHz mono PCM, исходный текст, контекст
по 0,5 секунды с каждой стороны и контрольные суммы. Неизменяемая база находится
в `local/training-staged/dataset.json`. Неподходящие исходные аудио и пересечения
говорящих исключены. Полностью скрытые слова не восстанавливаются по догадке.

До выбора модели четыре группы из train зарезервированы в новый `holdout`.
ASR-аудит и forced alignment работают только с train/validation. Test с ранее
просмотренными примерами не является независимым финальным тестом.

`audit-labels` записывает подсказки ASR. `suggest-alignment` предлагает границы
слов по предоставленному тексту. Оба процесса оставляют разрешение на обучение
выключенным. Алгоритм выравнивания способен разместить и неверный текст,
поэтому успешный forward не подтверждает правильность фразы.

Страница разметки сохраняет `text_reviewed` и `alignment_reviewed` отдельно.
Если человек проверил только текст, он остаётся полезной разметкой, но ещё
не попадает в обучающий экспорт. `export-reviewed` принимает только полностью
проверенные примеры, сверяет версию базы и аудио и физически обрезает WAV по
выбранным границам. Присвоенный split берётся из базы, его нельзя изменить
решением в форме проверки. Выходной каталог должен быть новым.

Для GigaAM v3 RNN-T используются произнесённые русские формы имён и чисел.
Например, «це зет» вместо `CZ`, если именно так звучит запись. Пунктуация,
регистр и ё/е нормализуются. Неподдерживаемые символы не удаляются: такие
пары сохраняются в общем JSONL и отдельно перечисляются как исключённые из
GigaAM TSV. Форматирование будущих субтитров остаётся отдельным этапом.

Проверенная первая пачка содержит 98 полностью подтверждённых примеров:
84 train и 14 validation. Для GigaAM в train подходят 82 строки. Две записи
с `SSG` и `5.56` ожидают уточнения произнесённой формы. Ещё семь решений из
пачки не содержат полного подтверждения, 15 отклонены. Эти числа относятся
к импортированному файлу, последующая разметка может менять состав.

Примерно 1,8 минуты проверенного звука достаточно для проверки формата и
пробного обучающего цикла. Этого мало для надёжных выводов об улучшении модели.
Перед оценкой результата дообучения нужна более широкая проверенная validation,
сохранённая отдельно от train. Не следует обучать все веса долго на крошечной
выборке ради уменьшения ошибки на этих же записях.

`development.jsonl` содержит train и validation для разборов ошибок до обучения.
Его оценки маркируются `development_diagnostic_includes_train`. Итоговые
показатели качества после обучения на этом наборе не публикуются как test.

Для повторной оценки после ручной проверки нужно использовать новые общие
аудиофрагменты, обрезанные по проверенным границам. Нельзя просто подставить
исправленный текст к старым ASR-ответам, если изменилось само аудио.

```powershell
docker compose run --rm tools prepare-reviewed-evaluation `
  --manifest local/training-reviewed-v1/validation.jsonl `
  --output local/evaluation/reviewed-v1
```

Первые примеры очереди намеренно содержат сложные случаи, выбранные по ошибкам
large-v3. Их отдельный WER не является оценкой на случайной репрезентативной
выборке. Результат на них следует публиковать отдельно от общего сравнения.

## Что измерять

- WER и CER для слов и букв.
- Пропуски мата и долю слова, оставшуюся слышимой после запикивания.
- Лишние сигналы на обычных словах.
- Ошибки говорящего и отдельные случаи одновременной речи.
- Ошибки начала и конца реплики.
- Боковые отступы, плавность, монтаж и синхронизацию хотбара обычными проверками.

## Ограничения текущего корпуса

Субтитры являются редакторской разметкой, а не гарантированно дословным ASR
датасетом. Переводы, маскированный мат, фоновые голоса, короткие нарезки и
накладывающиеся реплики требуют проверки. Цвет подписи задаёт предполагаемого
говорящего, но сам по себе не доказывает личность голоса во всех проектах.

Нельзя обучать модель на всех проектах и затем объявлять результат на этих же
записях улучшением. Нельзя измерять полноту распознавания мата только на
выборке, из которой все маскированные слова уже исключены.
