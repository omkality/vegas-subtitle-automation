# Сборка и выпуск

Базы контейнеров закреплены по версии и digest. Python-зависимости устанавливаются
из lock-файлов с проверкой хешей и только из готовых wheel-файлов. Основные
образы tools/gpu не содержат CUDA SDK, компиляторов или PyTorch. Запуск выполняется с UID 1000.
FFmpeg поставляется в зафиксированной зависимости imageio-ffmpeg, отдельный
пакет с графическими зависимостями ОС не устанавливается.

CUDA 12.8.1/cuDNN 9 и Python 3.12 выбраны для проверенного стека CTranslate2.
Новая версия сама по себе не доказывает лучшего качества ASR. Обновления баз,
lock-файлов и GPU-библиотек проходят тесты и локальную проверку CUDA.

CI проверяет PR и main. Он не получает доступ к приватному корпусу, секретам
моделей или GPU. CPU-образ используется для тестов и обработки метаданных.
Распознавание проверяется в отдельном GPU-контейнере локально.

Release workflow публикует CPU/GPU-образы в GHCR только после push релизного
тега. Имена включают версию и SHA коммита. Плавающий latest не создаётся.
Привилегии packages:write выданы только release job. Публикация не выполняется
из pull request. SBOM и provenance включены. Actions закреплены commit SHA.

Сам release workflow пока не запускался в GitHub. Его наличие в репозитории
не означает состоявшуюся публикацию или успешное удалённое выполнение CI.

Профиль `research` использует отдельный `Dockerfile.research` с закреплённым
PyTorch 2.10.0 CUDA 12.8 runtime образом. Установленные Torch/torchaudio берутся
из этой базы. Другие зависимости устанавливаются с хешами в собственное venv
с доступом к пакетам базы. Системное Python-окружение не изменяется. Единственный
sdist в lock-файле, ANTLR runtime для OmegaConf, является Python-пакетом и
собирается без изолированной загрузки незакреплённых build dependencies.

T-one работает через onnx-asr 0.12.0 и ONNX Runtime GPU 1.23.2, совместимый с
CUDA 12/cuDNN 9 в базе. Доступность CUDA проверяется при загрузке. Дополнительно
короткий synthetic warmup записывает профиль, в котором должны присутствовать
CUDA kernels. При CPU fallback запуск отклоняется. KenLM не использовался.
Профиль сохраняется в local/runtime/onnx-profile. Для остальных новых моделей
используются штатные Transformers-классы и локальные safetensors без remote code.

Профиль `review` доступен только через 127.0.0.1:8765 и монтирует только local/.
Исходные диски ему не передаются. Сохранение проверяет Origin, хеш базы и ID
примеров. WAV поддерживают HTTP Range, чтобы браузер точно переходил к выделению.
Сервис оставляют работающим, пока человек проверяет разметку. Для завершения
используйте `docker compose --profile review stop review`, без остановки других
контейнеров или удаления данных.

Для обновления Python lock-файлов используйте uv pip compile с теми же extras
и --generate-hashes. Проверяйте изменения в PR и повторяйте тесты. Загрузка
новых версий не должна происходить при каждом запуске inference.
